# 配車管理（/haisha）の復旧手順書

不具合や操作ミスがあったときに、**元に戻す**ための手順です。症状から探してください。
（最終更新：2026-11-09）

## 0. まず落ち着いて確認すること

| 症状 | まず見る場所 |
|---|---|
| 画面の表示がおかしい・ボタンが動かない | ページを完全に再読み込み（Ctrl＋F5）。直らなければ「1. 画面（プログラム）を元に戻す」 |
| 予約の中身・担当者・状態を間違えた | 「2. 予約を元に戻す」 |
| データが消えた・壊れた | 「3. データベースを復旧する」 |
| 確認のサイン（①〜④）を間違えた | 該当のチェックを外して取り消し、もう一度サイン（取り消すと確認メッセージが出ます） |
| マニュアル・資料が壊れた | 「4. マニュアル・資料を元に戻す」 |

## 1. 画面（プログラム）を元に戻す

画面の動きは Git で管理していて、本番サイトは `main` ブランチが自動で公開されます（Vercel）。
**安定していた版には、名前（タグ）が付けてあります。**

| タグ | 内容 |
|---|---|
| `haisha-v0-before-2026-10-20` | 2026-10-20より前（状態が6つだった時点） |
| `haisha-v1-statuses5` | 状態を5つ（通常／変更あり／キャンセル／貸切／ジャンボ）に整理した時点 |
| `haisha-v2-paper-only` | 「予約受付表（紙）のみ」（受付表ボタン）を足した時点 |
| `haisha-v3-four-checks` | チェック項目4つ（①〜④）にした時点 |
| `haisha-v4-stable-2026-11-09` | 2026-11-09時点の安定版（バックアップボタンを足した時点） |

### 1-A. 一番かんたん：Vercelで、前の公開に戻す（コマンド不要・1分）
1. https://vercel.com にログインし、このサイト（fujitaxi-site）のプロジェクトを開く
2. 「Deployments」で、正常だったころの公開を選ぶ
3. 「…」→「**Promote to Production**」（または「Instant Rollback」）を押す

### 1-B. 不具合の変更だけを取り消す（Git）
```bash
git log --oneline -20          # 不具合のコミットを探す（例：abc1234）
git revert abc1234             # その変更だけを打ち消す新しいコミットを作る
git push origin main           # 本番に反映される（1〜2分）
```

### 1-C. 安定版そっくりに戻す（Git）
```bash
git checkout -b rollback haisha-v4-stable-2026-11-09
git push origin rollback:main --force   # ※履歴を書き換えるので、他の人の作業がないことを確認してから
```
※ 迷ったら 1-A か 1-B にしてください（履歴が残り、さらに戻せます）。

### 注意（過去の教訓）
- コミットするときは、**対象のファイルを指定して** `git add` する（`git add docs` のように広く指定しない）。
  過去に、関係のない資料（営業資料・通所サービス）を公開リポジトリに載せてしまった。
- このリポジトリは**公開**です。社内の資料・個人情報・パスワードを入れない。

## 2. 予約を元に戻す（画面から）

日別の配車ボードの下の「**変更履歴**」で、予約の追加・変更・削除が新しい順に残っています（DBが自動で記録）。
- 管理者のロックを解除すると、各行に「**元に戻す**」が出ます。押すと、その変更だけを取り消せます。
- 削除した予約も、履歴の「削除」から復元できます。
- 注意：復元すると、時刻変更の前後の紐付け（「→ 08:00に変更」の足跡）が失われることがあります。
- 「変更履歴で見る」「変更内容を見る」で、その予約の履歴だけに絞れます。
- 取り込み（CSV）を間違えたときは、変更履歴で、その取り込みで追加・変更された行をまとめて確認し、必要な分を元に戻します。

## 3. データベースを復旧する

### 3-A. バックアップをダウンロードしておく（**毎週、または大きな変更の前に**）
1. `/haisha?admin` を開き、「管理者ロック解除」でログイン
2. 管理者のバーの「**バックアップをダウンロード**」を押す
3. `haisha-backup-日付-時刻.json` が保存される（予約・変更履歴・引き継ぎ・取り込み履歴・乗務割・確認のサイン・スタッフ・シフト）
4. 保存した場所（OneDrive など）を決めておく

ファイルの中身は、表ごとの行の一覧です（`tables.dispatch_reservations` など）。
壊れたデータを、このファイルと見比べて、必要な行だけ Supabase の画面（Table Editor）で直せます。

### 3-B. Supabase側のバックアップ
- Supabase の「Database → Backups」に、自動バックアップがあれば、そこから復元できます（プランによって、ある・ないが違います）。
- 変更履歴（`dispatch_history`）にも、すべての変更の前後の値が残っています。

### 3-C. 表を作り直す（表そのものが消えたとき）
表を作るSQLは、仕様書 `docs/haisha-supabase-spec.md` に、**変更の節ごとに載っています**。
主な表：

| 表 | 内容 | SQLの場所 |
|---|---|---|
| `dispatch_reservations` | 予約（本体） | 仕様書の前半、§5.62（状態）、§5.83（`paper_checked`列） |
| `dispatch_history` | 変更履歴（DBトリガーで自動記録） | 仕様書の前半 |
| `dispatch_handovers` | 引き継ぎ・申し送り | 仕様書の前半 |
| `dispatch_confirmations` | ④ 全て確認済み | §5.72 |
| `dispatch_first_checks` | ① 日勤・シングルチェック済み | §5.79 |
| `dispatch_check_extras` | ② 日勤・Wチェック完了／③ 遅番・シングルチェック済み | §5.87 |

## 4. マニュアル・資料を元に戻す

- 原本は `docs/manuals/`（HTML＋PDF）にあります。Git の履歴から、過去の版を取り出せます：
```bash
git log --oneline -- docs/manuals/haisha-manual-driver.html   # 履歴を見る
git checkout <コミット> -- docs/manuals/haisha-manual-driver.html   # その版に戻す
```
- 公開しているマニュアル（Artifact）にも、過去の版が残っています。
- 過去に、運転手用マニュアルの節が消える不具合がありました（書き換えの範囲の誤り）。大きく書き換えたあとは、**節の数（見出し）が減っていないか**を確認してください
  （管理者用：14節、乗務員用：5節）。

## 5. 不具合が出たときに、連絡してほしいこと

- いつ（日付・時刻）、どの画面（日別／全体／予約一覧）、何を押したか
- 画面に出た文言（スクリーンショットがあると確実）
- 使っている端末（スマホ／タブレット／パソコン）と、画面の文字サイズ

## 6. 変更の記録

どの変更を、いつ、なぜ行ったかは、`docs/haisha-supabase-spec.md` の §5.62〜（日付つき）に、すべて書いてあります。
不具合の原因を探すときは、まず該当する節を読んでください。
